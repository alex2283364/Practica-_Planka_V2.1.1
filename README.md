# Практическая работа по DevOps. Платформа управления проектами Planka

Данный проект представляет собой полноценное решение для развертывания и мониторинга платформы управления проектами **[Planka](https://planka.cloud/)**. В рамках практической работы был реализован комплексный подход к автоматизации: контейнеризация приложения с помощью Docker, настройка системы мониторинга на базе **Prometheus** и **Grafana**, а также организация сбора и анализа логов через **Loki** и **Promtail**.

## 1. Структура проекта

Проект построен по модульному принципу, что обеспечивает гибкость и простоту в управлении.

```text
.
├── .github/                     # Конфигурация CI/CD пайплайнов (GitHub Actions)
├── monitoring/                  # Полный стек для мониторинга и логирования
│   ├── docker-compose.monitoring.yml    # Docker Compose для сервисов мониторинга
│   ├── grafana/                 # Конфигурация Grafana
│   │   ├── dashboards/          # Готовые дашборды (бизнес-метрики Planka)
│   │   └── provisioning/        # Автоматическая настройка источников данных
│   ├── loki/                    # Конфигурация Loki (сбор и хранение логов)
│   ├── prometheus/              # Конфигурация Prometheus (сбор метрик)
```

## 2. Особенности реализации
###2.1 Контейнеризация (Docker)
Приложение Planka упаковано в Docker-образ, собранный с использованием многостадийной сборки:

Стадия 1 (Server): Сборка серверной части на node:20-alpine. Устанавливаются зависимости, выполняется сборка проекта, а затем удаляются dev-зависимости для уменьшения финального размера образа.

Стадия 2 (Client): Сборка клиентской части на node:20-alpine. Собирается статика для фронтенда.

Стадия 3 (Final): Финальный образ на node:20-alpine. Копируются только собранные артефакты (Node.js-модули, dist сервера и статика клиента). Создан непривилегированный пользователь appuser для повышения безопасности. Контейнер слушает порт 1337 и включает healthcheck для контроля состояния.

### 2.2 Обратный прокси (Nginx)
Для маршрутизации трафика и улучшения производительности перед приложением запускается Nginx. Он выполняет следующие функции:

Проксирование всех запросов к бекенду Planka.

Поддержка WebSocket-соединений (необходимо для работы реального времени в Planka).

JSON-логирование: все запросы логируются в структурированном формате, что позволяет легко парсить их для анализа.

### 2.3 Мониторинг и логирование
Для обеспечения наблюдаемости (observability) системы развернут современный стек:

- Метрики (Prometheus + Node Exporter + cAdvisor). Prometheus собирает метрики с:
  - Node Exporter — системные метрики хоста (CPU, память, диски).

  - cAdvisor — метрики использования ресурсов контейнерами.

  - Nginx — метрики HTTP-запросов (доступны через экспортер).

- Grafana используется для визуализации метрик. В репозитории уже присутствует дашборд PlankaBusinessMetrics.json с ключевыми бизнес-показателями.

- Логи (Loki + Promtail). Loki — сервер для агрегации логов.
  
- Promtail — агент, который собирает логи:

 - Системные логи из /var/log.

 - Логи Docker-контейнеров.

 - Логи Nginx (JSON-формат) из папки nginx/logs/.

### 2.4 CI/CD (GitHub Actions)
Настроен автоматический пайплайн при каждом пуше в ветку main:

- Проверка синтаксиса Docker Compose.

- Проверка доступности приложения через smoke_test.sh.

- Сборка Docker-образа.


## 3. Развертывание проекта
### 3.1 Требования
Установленный Docker и Docker Compose.

Git для клонирования репозитория.

### 3.2 Шаги по запуску
Клонировать репозиторий:

```bash
git clone https://github.com/alex2283364/Practica-_Planka_V2.1.1.git
cd Practica-_Planka_V2.1.1
```
Запустить скрипт автоматического развертывания:
```bash
# Дать скрипту права на выполнение (только при первом запуске)
chmod +x setup.sh

# Запустить установку
./setup.sh
```
Скрипт выполняет:
1. Проверяет наличие необходимых компонентов
2. Генерирует .env файл. Если он есть - пропускается
3. Клонирует репозиторий оригинального проекта с указанием его версии. Если проект уже клонирован - пропускается
4. Сборка образов
5. Запуск проекта
6. Загружает заготовленные демо-данные. При повторном запуске бд стирается полностью, и заново загружаются заготовленные данные
7. Выводит итоговый статус и проверку доступности

Запустить стек мониторинга:
Для запуска Prometheus, Grafana, Loki и Promtail используйте отдельный Compose-файл.

``` bash
docker compose -f monitoring/docker-compose.monitoring.yml up -d
```
Grafana будет доступна по адресу: http://localhost:3001 (логин/пароль по умолчанию: admin/admin).

Prometheus доступен на порту 9090.

Loki доступен на порту 3100.

Проверка работоспособности:

- Убедитесь, что все контейнеры запущены: docker compose ps и docker compose -f monitoring/docker-compose.monitoring.yml ps.

- Откройте Planka в браузере. При первом запуске будет создан администратор, указанный в переменных DEFAULT_ADMIN_*.

- Войдите в Grafana и проверьте дашборд с бизнес-метриками.

## 4. Мониторинг: что и как отслеживается

**planka-app** — для быстрой проверки, живо ли приложение.

**PlankaBusinessMetrics** — для анализа пользовательского опыта и производительности.

**system-health** — для контроля над состоянием сервера и инфраструктуры.

## 5. Управление и обслуживание
### 5.1 Просмотр логов
Логи Nginx в реальном времени можно посмотреть командой:

``` bash
docker compose logs -f nginx
```
Логи всех сервисов мониторинга:

``` bash
docker compose -f monitoring/docker-compose.monitoring.yml logs -f
```
### 5.2 Остановка и удаление сервисов
Остановка всех контейнеров

``` bash
docker compose down
docker compose -f monitoring/docker-compose.monitoring.yml down
```
Удаление томов с данными (база данных, метрики, логи)

``` bash
docker compose down -v
docker compose -f monitoring/docker-compose.monitoring.yml down -v
```
